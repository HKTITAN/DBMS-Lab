\section*{\sffamily\color{blue800}Abstract}
\addcontentsline{toc}{section}{Abstract}

Phase 1 of this term paper argued that the memory of an AI agent is a
database. Phase 2 tests that argument against the systems and the
benchmarks the field has actually published.

Four agent memory systems are read as data models: \textbf{MemGPT},
which pages a memory hierarchy the way an operating system pages virtual
memory \cite{memgpt}; \textbf{Zep}, which stores memory as edges of a
temporal knowledge graph and invalidates an edge instead of deleting it
\cite{zep,graphiti}; \textbf{Mem0}, which gives a writer four explicit
operations over a memory store \cite{mem0}; and \textbf{A-MEM}, which
argues that a fixed schema is itself the problem \cite{amem}. Two
benchmarks supply the evidence about what fails: LongMemEval isolates
five abilities of a long-term memory \cite{longmemeval}, and LoCoMo
builds conversations of about 300 turns across as many as 35 sessions
\cite{locomo}.

The comparison finds that three of the four have converged, from outside
the database literature, on one shape: a subject--predicate--object
triple carrying a validity interval, an entity registry that gives a
thing one name, and a provenance edge back to the text that supported the
claim. That is a database schema, and the questions the database
community asked about it are fifty years old.

The findings are that structure pays and is measured to pay --- Mem0
reports a 26\% relative improvement over a deployed baseline and more
than 90\% fewer tokens than full context \cite{mem0}, and Zep reports up
to 18.5\% higher accuracy with 90\% lower latency \cite{zep} --- but that
three guarantees a database declares are still missing everywhere. No
system declares uniqueness, so identity is decided by similarity rather
than by key. No paper reports what happens when two writers touch one
memory at once. And no system uses the temporal standard that has existed
since SQL:2011, although two of them implement its idea by hand.

The recommendation follows from those gaps: declare the schema where the
data is, give the fact relation a temporal key, and make the update an
operation the writer names rather than a side effect of a write.

\section{Comparison}
\label{sec:cmp}
%=====================================================================

Phase 1 asked how an agent memory carries a fact across a session
boundary. That separates designs but does not price them. This phase asks
a narrower question with a harder answer. \emph{Read four published
systems as data models: what has each one declared, and what can each one
refuse?}

\subsection{The four systems, and why these four}

The four are chosen because each takes a different position on the one
question this topic turns on, which is how much structure the memory
should declare in advance.

\textbf{MemGPT} takes the operating-system position. It treats the
context window as physical memory and everything else as disk, and it
moves data between the two tiers, ``inspired by hierarchical memory
systems in traditional operating systems that provide the appearance of
large memory resources through data movement between fast and slow
memory'' \cite{memgpt}. The model itself issues the paging calls. There
is no schema, because paging does not need one.

\textbf{Zep} takes the temporal-database position. Memory is a graph of
entity nodes joined by edges, and every edge carries both when the fact
was true and when the graph came to believe it, so a contradicted edge is
invalidated rather than removed \cite{zep,graphiti}.

\textbf{Mem0} takes the data-manipulation position. Extraction proposes
candidate memories, and the update phase resolves each candidate into one
of four operations --- \code{ADD}, \code{UPDATE}, \code{DELETE} or
\code{NOOP} --- against what is already stored \cite{mem0}.

\textbf{A-MEM} takes the opposing position, and the comparison is weaker
without it. It argues that existing systems ``rely on fixed schemas or
operation structures'' and that this limits adaptation to new tasks,
proposing instead notes that link themselves into a network which emerges
from content rather than from a declared shape \cite{amem}.

\subsection{What the comparison separates}

It does not separate them on ambition: all four are trying to make an
agent remember across sessions, and all four report progress at it. It
separates them on \emph{what the store is allowed to promise}.

Read down the last row of Table~\ref{tab:designs}. Only one of the four
can refuse a write, and only for the part it has declared. In every other
column the guarantee is a convention held by the program that writes,
which means it holds exactly as long as every writer is well behaved.
That is the axis \S\ref{sec:findings} measures, and it is the axis on
which fifty years of database results have something to say.

\section{Findings}
\label{sec:findings}
%=====================================================================

Most of the findings below carry the name of an older database
phenomenon, because that is what they turn out to be.

\subsection{Three of the four converged on one schema}
\label{sec:f1}

\finding{F1} Zep, Mem0's graph variant and the wider family all arrive at
the same three parts, independently and from outside the database
literature: a triple of subject, predicate and object; an interval saying
when that triple was true; and an edge back to the text that supported
it. Zep states the temporal half explicitly, giving each edge both the
interval over which the fact held and the interval over which the graph
believed it \cite{zep}.

That is a schema, and naming it as one is the whole contribution of
reading these systems as data models. A relation with a compound key, a
validity interval and a provenance foreign key is not a new object. It is
the object Codd's successors spent the 1990s formalising, and the
questions that follow --- what is the key, what refuses a duplicate, what
happens when two intervals overlap --- are already answered.

The convergence is partial, and Table~\ref{tab:parts} is careful about
where. Only Zep holds all four parts; Mem0 reaches the first and the
last; and the two systems that declare no schema hold none of them, which
is consistent rather than careless, because neither is trying to.

that the structured designs are not paying for their structure in speed:
both report large latency and token reductions, because a memory that
retrieves a few relevant rows sends less to the model than one that
resends the conversation. The second is \S\ref{sec:f8}.

\subsection{The measured failures are the ones a validity interval addresses}
\label{sec:f3}

\finding{F3} LongMemEval isolates five abilities of a long-term memory,
two of which --- temporal reasoning and knowledge updates --- are exactly
the two a validity interval exists to serve, and it measures about a 30\%
accuracy drop for commercial assistants across sustained interactions
\cite{longmemeval}.

LoCoMo reaches the same place from a different direction. Its
conversations run to roughly 300 turns and as many as 35 sessions, and it
finds that models ``exhibit challenges in understanding lengthy
conversations and comprehending long-range temporal and causal dynamics
within dialogues'', still lagging human performance substantially even
when given long context or retrieval \cite{locomo}.

Neither benchmark was built to argue for a schema. Both nevertheless
locate the difficulty in the part of memory that changes over time, which
is the part a temporal relation is for.

\subsection{The systems disagree about who owns the update}
\label{sec:f4}

\finding{F4} This is the update anomaly, and the four systems answer it
in four different places. MemGPT gives the decision to the model, which
issues the call that moves data between tiers \cite{memgpt}. Zep gives it
to the engine, which closes the old edge when a new one contradicts it
\cite{zep}. Mem0 gives it to the writer, which must resolve every
candidate into \code{ADD}, \code{UPDATE}, \code{DELETE} or \code{NOOP}
\cite{mem0}. A-MEM gives it to the network, which re-links notes as they
arrive \cite{amem}.

Only Mem0's answer is a data manipulation language in the ordinary sense:
a closed set of operations, each with a defined effect, chosen at the
point of writing. The other three infer the operation from context, which
is exactly the design a declared \code{UPDATE} was invented to replace.

\subsection{Identity is decided by similarity, not by key}
\label{sec:f5}

\finding{F5} A memory has to decide when two mentions are the same thing.
Zep resolves this with an entity node, Mem0 by similarity, A-MEM by
emergent linking, MemGPT not at all. None of the four declares
uniqueness, and a store with no unique index cannot refuse the second
introduction of a thing it already holds.

This has a theory, and the theory is older than the problem. Swoosh
formalises match and merge as generic operators and defines the
transitive closure a resolution has to reach before it is finished
\cite{swoosh}: if $A$ merges with $B$ and $B$ with $C$, the result is not
settled until $A$, $B$ and $C$ are one. A pairwise similarity test does
not reach that closure by itself, so duplicate identities survive in
exactly the systems that resolve identity by similarity.

\subsection{Nobody reports what two writers do to one memory}
\label{sec:f6}

\finding{F6} Every one of the four papers evaluates a single writer. None
of them reports a concurrent-write experiment, and none declares an
isolation level.

This matters because agent memory is now shared by construction: a team
of agents, or a team of people and their agents, writes to one store. The
failure that follows is the oldest one in the transaction literature.
Gray's account sets out the lost update and the degrees of consistency
that permit it \cite{gray1976}: two writers read the same value, each
computes a new one from what it read, and the second write erases the
first.

Every design in Table~\ref{tab:designs} has that shape, because every one
of them updates by reading first. Mem0 must retrieve the existing
memories before it can decide whether a candidate is an \code{ADD} or an
\code{UPDATE} \cite{mem0}; Zep must find the edge a new fact contradicts
before it can invalidate it \cite{zep}; A-MEM's evolution step revises
the notes a new note links to, so its exposure grows with the linking
\cite{amem}. In each case the decision is computed from a value read a
moment earlier, and nothing in the write says what that value was.

The database answer is one line: make the write conditional on the state
the reader saw, against a key the store has declared. That is what an
\code{ON CONFLICT} clause or a compare-and-set against a version does,
and it turns a lost update into a refused write the caller can retry.
None of the four is documented as having one, and until a paper measures
two writers on one memory, nobody knows the size of the problem.

\subsection{The temporal standard already exists and none of them uses it}
\label{sec:f7}

\finding{F7} Zep implements two time axes by hand \cite{zep}. SQL:2011
standardised the same separation more than a decade earlier, as
application-time period tables for when a row is true in the world and
system-versioned tables for when the database held it, with period-scoped
\code{UPDATE} and \code{DELETE} and automatic history rows
\cite{sql2011}.

The gap is not that the agent-memory systems are wrong. It is that they
are re-deriving a solved problem, and paying for it in the usual way: a
hand-built temporal column has no period-scoped update, no automatic
history, and no way for the engine to refuse two intervals that overlap
when they should not. Figure~\ref{fig:gap} puts that gap, and the two
from \S\ref{sec:f5} and \S\ref{sec:f6}, on one axis.

\subsection{The results cannot be compared with each other}
\label{sec:f8}

\finding{F8} This finding cuts against the argument the rest of this
report is making, and it belongs here for that reason.

Read Table~\ref{tab:results} again as a comparison and it collapses.
Mem0's 26\% is a relative improvement in an LLM-as-a-judge metric over a
deployed baseline on LOCOMO \cite{mem0}. Zep's 94.8\% is an absolute
accuracy against MemGPT's 93.4\% on DMR, and its 18.5\% is an improvement
against baseline implementations on LongMemEval \cite{zep}. Different
benchmarks, different baselines, different metrics, and in one case a
relative figure set beside an absolute one.

So no ranking of these systems can be read off their own papers, and this
report does not offer one. What the numbers jointly support is the
weaker, sufficient claim of \S\ref{sec:f2}: structuring memory measurably
beats resending the conversation. Anything stronger would need one
benchmark, one baseline and one metric across all four, which nobody has
yet run.

\section{Recommendation}
\label{sec:rec}
%=====================================================================

The recommendation is not that these systems should have been built on
PostgreSQL. Three of the four earn their design: paging is the right
answer to a context limit, an emergent network is a real position on
adaptability, and both structured systems measurably beat resending the
conversation. The recommendation is narrower. \textbf{Declare the parts
that are already a schema, and let the store enforce them.}

Six rules follow. Each names the finding that forces it; F1 forces none,
being the framing result rather than a defect.

\begin{enumerate}
  \item \textbf{Declare the key where the data is.} A unique index on the
        canonical name of a thing, plus one \code{ON CONFLICT} statement,
        removes the window a read-then-write update cannot close and
        stops one real thing being introduced twice. \emph{(F5, F6)}
  \item \textbf{Give the fact relation a temporal key.} An exclusion
        constraint over a range type refuses the write that would let one
        subject hold two objects at once, so no scan has to find it
        afterwards. \emph{(F7)}
  \item \textbf{Use the standard, not a hand-built pair of columns.}
        Application-time period tables and system-versioned tables give
        period-scoped updates and automatic history that hand-rolled
        date columns do not \cite{sql2011}. \emph{(F7)}
  \item \textbf{Make the update an operation the writer names.} Mem0's
        \code{ADD}, \code{UPDATE}, \code{DELETE} and \code{NOOP} is a data
        manipulation language; inferring the operation from context is
        the anomaly the language replaced \cite{mem0}. \emph{(F4)}
  \item \textbf{Resolve identity to closure, not pairwise.} Match and
        merge have to reach a transitive closure before a resolution is
        finished \cite{swoosh}, and a similarity threshold does not reach
        it alone. \emph{(F5)}
  \item \textbf{Report the benchmark, the baseline and the metric
        together.} A number without all three cannot be compared with
        another number, which is the state of the field today.
        \emph{(F2, F8)}
\end{enumerate}

\textbf{When, and with what caveat.} These rules earn their cost once a
memory is shared --- more than one writer, or a store outliving the
person who filled it. Below that line a paged context or an emergent
network is the better engineering choice, and the structure is a
liability. The caveat is F8: every quantitative claim here is a figure a
system reports about itself on a benchmark of its own choosing, so this
report compares designs and does not rank them. What it settles is
firmer. A memory that arrives at triples with validity intervals, an
entity registry and a provenance edge has arrived at a database schema,
and the only question left is which of the guarantees it does without,
and what it does instead.
